# Базовый минимум

Рабочее приложение строительной группы: деньги, материалы и работы в одном месте.
Одно приложение, у каждой роли своё рабочее место. Работает и на телефоне, и на компьютере.

Это **демо-версия интерфейса**. Все люди, компании и суммы вымышлены. Сервера нет: данные хранятся
в браузере (localStorage), и то, что вы вносите, видно только вам на этом устройстве.

## Рабочие места

| Роль | Что делает | Прямая ссылка |
| --- | --- | --- |
| Прораб | Потребности в материалах, получение, материалы на объекте, план и факт работ, АВР, геометрия, замечания | `#/as/foreman` |
| Собственник | Деньги группы, финансы до операции, платёжный календарь, согласования, объекты, аналитика | `#/as/owner` |
| Менеджер торгового направления | Очередь потребностей, маршруты позиций, склад, заказы, обеспечение объектов | `#/as/manager` |
| Снабженец | Очередь закупок, карточка закупки, заказы поставщикам, поставки, заявки на оплату | `#/as/supplier` |
| Экономист, администратор | Финансовый центр, операции, транзиты и сверка, планирование, заявки, объекты, справочники, нормы, права, журнал | `#/as/admin` |

Добавьте хвост ссылки к адресу сайта, чтобы открыть приложение сразу под нужной ролью.
На телефоне сайт можно добавить на главный экран, и он откроется как приложение.

## Сквозные сценарии, которые можно пройти

1. **Материалы.** Прораб создаёт потребность, менеджер делит каждую позицию по маршрутам (склад, заказ,
   снабженец, уточнение), снабженец закупает, прораб подтверждает получение, материал появляется на объекте.
2. **Деньги.** Сотрудник создаёт заявку, собственник согласует, экономист оплачивает, операция попадает
   в реестр, платёжный календарь и прогноз остатка пересчитываются.
3. **Работы.** Прораб вносит замеры и факт, формирует АВР, руководитель проекта принимает объёмы.
4. **Собственник.** От общей суммы по группе до конкретной операции за несколько нажатий.

## Что добавлено по дополнению к концепции

- **Навигация и контекст.** Путь к экрану («Объекты / объект / этаж / Геометрия»), место работы (объект, этаж, помещение) подставляется в формы, «Назад» возвращает в то же место списка с теми же фильтрами, форма с введёнными данными не закрывается без вопроса, черновик потребности сохраняется на устройстве.
- **Запуск от задачи.** Кнопка «Что нужно сделать»: список типовых задач роли с подсказкой из текущего состояния процессов.
- **Геометрия по этажам.** Этаж, помещение, зоны, ниши, выступы и откосы, неровности с местом и величиной, способ измерения. Версии этажа: черновик, на проверке, подтверждена, заменена. Акт формируется на весь этаж. Подтверждённые замеры не перезаписываются: правка открывает новую версию с причиной.
- **Работы из геометрии.** Объём работы берётся из подтверждённой версии и хранит ссылку на неё. Потребность рассчитывается по технологической карте и хранит основание расчёта.
- **Получение.** Наименование и код из документа отгрузки для физической сверки, место хранения, позиции вне заказа регистрируются как временные записи.
- **Каталог.** Семейства и позиции, единицы хранения и применения, исходные позиции поставщиков, очередь нормализации.
- **Документы.** Общий реестр актов, потребностей, поставок, замечаний и заявок со ссылкой на исходную запись.
- **Замечание из любого места.** С привязкой к месту и исходной записи, сроком, ответственным и историей.
- **Технологии.** Голосовой ввод в текстовые поля, постоянная ссылка с QR-кодом для карточек, работа без связи после первого открытия. Страница «Технологии и интеграции» показывает, что работает в демо, а что ждёт сервера.

## Запуск на своём компьютере

```bash
npm install
npm run dev
```

Сборка для публикации: `npm run build`, результат в папке `dist`.

## Как устроено

- React, TypeScript, Vite. Маршруты через хэш, поэтому сайт работает на GitHub Pages без настройки сервера.
- `src/data` — модель, демо-данные, селекторы и действия. Экраны меняют данные только через `act`.
- `src/ui` — набор компонентов интерфейса и графики.
- `src/shell` — каркас: боковое меню на компьютере, верхняя и нижняя панели на телефоне.
- `src/roles` — экраны по ролям.

## Чего в демо нет

- Сервера, настоящего входа и общих данных между пользователями.
- Обмена с 1С, импорта банковской выписки, распознавания накладных, подключения дальномеров.
- Синхронизации между устройствами: черновики и данные остаются на том устройстве, где введены.
- Сохранения фотографий: хранится только их число.
